# Reaction 与 sticker 需求对齐

状态：用户已确认整体方案；最终决策已回填 GitHub Issues #3、#4 正文，尚未进入实现。

需求来源：[GitHub Issue #3（reaction）](https://github.com/wuye2325/lark-coding-agent-bridge/issues/3) 与 [GitHub Issue #4（sticker）](https://github.com/wuye2325/lark-coding-agent-bridge/issues/4)。后续实现以更新后的 issue 正文为准。
术语见根目录 `GLOSSARY.md`。

## 已确认：reaction 按事件驱动

- 目标仍限于本 Bot 发出的消息，进入会话前沿用访问策略校验。
- 添加与撤回均作为用户输入交给 Agent；输入应包含操作者、表情、目标消息与动作。
- 同一操作者添加不同表情、撤回表情、撤回后重加，均按实际收到的事件处理。
- 是否产生事件以飞书实际投递为准；同一次事件的重复投递沿用 SDK 去重。
- 不新增 JSON 或数据库等持久化记录，不承诺跨重启的事件去重。
- 撤销先前“目标消息＋操作者只接受首次添加”的决定。
- 此决定替代 issue #3 原先的“删除仅记日志”与“重复加／删不产生重复 run”要求；远端正文已同步。

场景：甲在消息 A 上加 OK、撤回 OK、再加 NO，Agent 分别收到添加 OK、撤回 OK、添加 NO 的输入；平台重复投递同一次添加事件不产生重复输入。输入进入既有会话队列，可能被合并为同一批次，不要求每个事件启动独立 run。

取舍：当前目标是让 Agent 感知用户的表情变化，而非保证一次性确认。持久化首次记录会增加存储、清理与失败恢复成本，因此取消该设计。

## 已确认：reaction 回执

- 添加事件通过校验并进入会话队列后，Bot 在目标消息上追加一个 ack 表情。
- 撤回事件只进入队列，不额外添加 ack。
- ack 添加失败仅记日志，不影响已入队事件的处理。
- ack 表示输入已接受，不表示 Agent 已完成处理；不额外发送文字收件回执。

## Sticker 的既有需求

- 下载表情图像，按普通图片附件路径传给 Agent。
- 下载失败时保留原始 sticker 文本，不阻塞本轮。
- 不新增表情语义或名称映射，保持其他媒体类型现有行为。
- 图片格式与大小沿用现有附件策略，不增加格式转换或动图处理。

## 验收要点

- Reaction 添加与撤回携带动作、表情、操作者及完整目标消息 ID，进入正确会话；话题会话保持隔离。
- 非本 Bot 消息、反查失败、访问策略拒绝时不入队、不添加 ack。
- 同一次事件的重复投递由 SDK 去重；真实的添加、撤回、重加保留。
- 添加事件接受后产生 ack，撤回不追加 ack；ack 失败不阻塞处理。
- Sticker 下载成功后作为 accepted image 交给既有 Agent 路径；下载失败保留原文并继续运行。
- 当前附件引用清理不匹配 `<sticker>` 标签；验收需覆盖最终 prompt 中失败降级的原文仍存在。
- Image/file/audio/video 的现有行为保持不变。
